# AAY Studio 개발 전달 명세

> 이 문서는 AAY Studio의 React 개발을 위한 제품·화면·정책 기준이다.  
> 구현 시 Figma를 시각적 기준으로 사용하고, 이 문서를 기능 및 예외 정책의 기준으로 사용한다.

---

## 1. 서비스 개요

### 1.1 서비스명

- 서비스명: **AAY Studio**
- 의미: **AI Automation Your Way**
- 기존의 “AI Automation Youtube”에서 확장한 명칭이다.
- 초기 게시 플랫폼은 YouTube 중심이지만, 향후 TikTok·Instagram 등으로 확장할 수 있어야 한다.

### 1.2 서비스 목적

AAY Studio는 사용자가 AI 영상 제작 전문지식이 없어도 숏폼 영상을 만들고 게시할 수 있도록 돕는 서비스다.

기본 흐름은 다음과 같다.

1. 사용자가 Google 계정으로 로그인한다.
2. 사용자가 템플릿 또는 직접 만들기를 선택한다.
3. 캐릭터·세계관·스토리와 영상 생성 정보를 입력한다.
4. AI가 영상 생성에 필요한 기획과 콘텐츠를 만든다.
5. 사용자가 결과물을 검토한다.
6. 연결된 플랫폼에 즉시 게시하거나 예약 게시한다.
7. 생성·게시한 영상은 라이브러리에서 관리한다.

### 1.3 핵심 가치

AAY Studio의 핵심은 단순히 영상 한 편을 생성하는 것이 아니라, **캐릭터·세계관·스토리의 연속성을 보존하고 필요에 따라 각각 재사용할 수 있게 하는 것**이다.

- 같은 캐릭터의 시각적 일관성을 유지한다.
- 같은 세계관을 여러 영상에서 재사용한다.
- 이전 이야기를 이어 쓰거나 새로운 옴니버스 이야기를 만들 수 있다.
- 캐릭터, 세계관, 스토리는 서로 분리된 데이터로 관리한다.

### 1.4 주요 사용자

- AI 영상 제작 경험이 적은 사용자
- 빠르게 숏폼 콘텐츠를 만들고 싶은 사용자
- 고정 캐릭터와 세계관으로 시리즈 콘텐츠를 운영하려는 사용자
- 영상 생성부터 게시까지 한 서비스에서 처리하려는 사용자

### 1.5 초기 언어

- MVP 기본 언어: **한국어**
- 서비스명 `AAY Studio`는 번역하지 않는다.
- 영어와 일본어는 추후 다국어 지원 대상으로 둔다.
- 다국어 구현 시 화면에 문자열을 직접 하드코딩하지 않고 번역 키 기반 구조를 고려한다.
- 영어·일본어 번역 문구와 검수 방식은 추후 확정한다.

## 2. 핵심 데이터 개념

### 2.1 캐릭터

캐릭터는 AI 모델명이나 생성 모델 설정이 아니라, **동일한 외형을 다시 생성하기 위한 시각 정보와 역할 정보**를 의미한다.

예시 정보:

- 이름
- 역할: 주인공 / 보조 인물
- 외형 특징
- 종 또는 인물 유형
- 의상과 소품
- 체형과 크기
- 말투 또는 성격
- 화면 노출 범위
- 참조 이미지
- 생성 시 유지해야 할 특징

정책:

- 같은 이미지 생성 모델을 사용했다고 동일 캐릭터가 보장되는 것은 아니다.
- 따라서 캐릭터의 시각 정보와 참조 정보를 별도로 저장해야 한다.
- 보조 인물도 시각적 일관성이 필요하면 캐릭터로 관리한다.
- 얼굴 전체가 나오지 않는 인물도 `턱 아래만 노출`, `손과 의상만 노출`처럼 필요한 시각 규칙을 저장할 수 있다.
- 하나의 영상에 여러 캐릭터를 추가할 수 있다.
- 캐릭터는 세계관이나 스토리와 독립적으로 재사용할 수 있다.

### 2.2 세계관

세계관은 여러 영상에서 공유되는 배경과 공통 설정이다.

예시 정보:

- 공간과 시대
- 직장·가족·사회적 관계
- 반복 등장하는 장소
- 분위기와 톤
- 세계 안에서 지켜야 하는 설정

정책:

- 기존 세계관을 선택하거나 새 세계관을 만들 수 있다.
- `세계관 선택`이 기본 상태다.
- `새 세계관 만들기`를 선택한 경우에만 세계관 입력 영역을 노출한다.
- 세계관은 캐릭터나 개별 스토리와 독립적으로 저장·재사용할 수 있다.

### 2.3 스토리

스토리는 특정 영상 또는 영상 시리즈에서 발생하는 이야기다.

정책:

- 기존 이야기를 이어가거나 새로운 이야기를 만들 수 있다.
- `스토리 선택`이 기본 상태다.
- 새 스토리 만들기를 선택한 경우에만 스토리 입력 영역을 노출한다.
- 새 세계관을 만드는 중에는 기존 세계관의 `이전 이야기 이어가기`를 사용할 수 없으므로 해당 옵션을 비활성화한다.
- 기존 세계관을 선택한 경우에만 해당 세계관에 연결된 이전 이야기를 이어갈 수 있다.
- 캐릭터와 세계관은 유지하면서 매 영상마다 새로운 이야기를 만드는 옴니버스 구조를 지원해야 한다.

### 2.4 세 개념의 관계

| 구분 | 독립 저장 | 독립 재사용 | 주요 목적 |
|---|---:|---:|---|
| 캐릭터 | O | O | 외형과 역할의 일관성 |
| 세계관 | O | O | 공통 배경과 설정의 일관성 |
| 스토리 | O | O | 이전 이야기 연결 또는 신규 이야기 생성 |

예시:

- 같은 캐릭터 + 같은 세계관 + 새로운 스토리
- 같은 캐릭터 + 새로운 세계관 + 새로운 스토리
- 새로운 캐릭터 + 기존 세계관 + 새로운 스토리
- 기존 캐릭터 + 기존 세계관 + 이전 스토리 이어가기

- 크레딧 결제와 환불

## 5. 페이지 구조

## 5.1 랜딩

목적:

- AAY Studio의 가치를 소개한다.
- 서비스 진입 CTA로 홈으로 이동시킨다(로그인 여부와 무관하게 접근 가능한 순수 소개 화면이다).

주요 요소:

- 서비스명
- 핵심 설명
- 홈으로 이동하는 CTA("콘텐츠 만들기 →")

**[2026-08-03 갱신 — 실제 Google 로그인 연동과 함께 반영]** 로그인 CTA는 랜딩이 아니라 홈에 있다. 랜딩은
비로그인 사용자도 볼 수 있는 순수 소개 화면이고, 클릭하면 항상 홈으로 이동한다(로그인 상태를 이 화면에서
확인하지 않는다).

## 5.2 홈

목적:

- 서비스의 시작점 역할을 한다. **로그인 여부에 따라 두 가지 상태를 보여준다.**
- 비로그인 상태: Google 로그인/가입 CTA를 보여준다.
- 로그인 상태: 만들기 방식으로 빠르게 진입시킨다.

주요 요소:

- 템플릿으로 만들기 안내
- 직접 만들기 안내
- 상태별 CTA: 비로그인 시 "로그인 또는 회원가입"(Google OAuth 트리거), 로그인 시 "콘텐츠 만들기 →"(`/create`로 이동)

문구 정렬:

- 홈 화면의 방식 설명은 왼쪽 정렬한다.

로그인 정책:

- MVP에서는 Google 로그인만 제공한다.
- 별도의 이메일 회원가입·비밀번호 입력 화면은 제공하지 않는다.
- 최초 Google 로그인 성공 시 서비스 계정을 생성하고, 기존 사용자는 동일한 Google 계정으로 로그인한다.
- 로그인 성공 후에도 홈에 머무른다(홈이 로그인 시작점이자 도착점이다).
- 로그인하지 않은 사용자가 로그인 이후 화면(만들기·라이브러리·마이페이지)에 접근하면 **홈으로** 이동시킨다.
- Google 로그인 취소 또는 실패 시 홈에 머무르고 오류를 안내한다.
- 폐쇄형 베타 기간에는 허용 목록에 없는 Google 계정의 가입 자체가 차단된다(`spec-addendum-backend.md` 6~9장).

## 5.3 작업 방식 선택

선택지:

### 템플릿으로 만들기

- AI 영상 제작 경험이 적거나 빠르게 만들고 싶은 사용자 대상
- 준비된 형식과 안내에 따라 간편하게 제작

### 직접 만들기

- 영상 구조와 내용을 세부적으로 설정하고 싶은 사용자 대상
- 사용자가 직접 기획 내용을 입력하고 조정

문구 정렬:

- 작업 방식 선택 화면의 설명은 가운데 정렬한다.

## 5.4 템플릿 적용 플로우

진행 순서:

1. 템플릿 선택
2. 캐릭터·세계관·스토리 설정
3. 출력 정보·생성 정보 확인 및 설정
4. 영상 생성
5. 생성 결과 검토
6. 게시 설정

특징:

- 한 화면에서 필요한 설정을 완료할 수 있도록 스크롤 구조를 사용한다.
- 우측 탭 메뉴를 선택하면 해당 설정 영역으로 자동 스크롤한다.
- 템플릿 사용자는 전문지식 없이 간편하게 만들고 싶은 사용자이므로 불필요하게 화면을 세분화하지 않는다.
- 템플릿 플로우에도 전체 진행 상태를 이해할 수 있는 스테퍼를 사용하되, 우측 탭과 시각적으로 충돌하지 않도록 구성한다.

캐릭터 영역:

- 기본 캐릭터를 표시한다.
- 캐릭터를 한 명씩 추가할 수 있다.
- 각 캐릭터의 역할과 시각적 유지 정보를 입력할 수 있다.

세계관 영역:

- 기존 세계관 선택이 기본값이다.
- `새 세계관 만들기` 선택 시에만 입력 영역을 노출한다.

스토리 영역:

- 기존 스토리 선택이 기본값이다.
- `새 스토리 만들기` 선택 시에만 입력 영역을 노출한다.
- 새 세계관 만들기 선택 시 `이전 이야기 이어가기`를 비활성화한다.

## 5.5 직접 만들기 플로우

진행 순서:

1. 사용자가 영상 아이디어와 기본 내용을 직접 입력
2. AI 기획 생성
3. AI 기획 확인 및 수정
4. 출력 정보·생성 정보 설정
5. 영상 생성
6. 생성 결과 검토
7. 게시 설정

정책:

- AI 기획은 사용자가 수정할 수 있어야 한다.
- 설정을 변경한 뒤 다시 생성할 수 있다.
- 생성 직전에는 필요한 크레딧을 표시한다.
- 필수값이 충족되지 않으면 다음 또는 생성 버튼을 비활성화한다.

## 5.9 라이브러리

목적:

- AAY에서 생성한 영상을 확인하고 게시 상태별로 관리한다.

검색·필터·정렬:

- 영상 제목 검색

- 제작 방식 필터
- 정렬 방식 선택
- 카드 보기 / 목록 보기 전환

보기 방식:

- 기본값은 카드 보기다.
- 보기 방식 선택 메뉴는 유지한다.
- 카드 보기와 목록 보기는 동일한 데이터와 상태를 사용한다.

초기 노출:

- 카드 보기에서는 한 줄에 3개를 노출한다.
- 최초 최대 6개, 즉 3개 × 2줄을 노출한다.
- 6개를 초과하면 하단에 `더보기` 버튼을 노출한다.
- 더보기를 누를 때마다 6개씩 추가로 로드한다.

영상 상태:

- 게시 완료
- 예약 게시
- 게시 실패

제외 상태:

- `게시 전` 상태는 사용하지 않는다.
- 게시 화면에서 즉시 게시 또는 예약 게시가 결정되므로 라이브러리의 관리 상태로 필요하지 않다.

영상 진입:

- 썸네일 또는 영상 제목을 선택하면 영상 상세로 이동한다.
- 제목 우측 메뉴 아이콘을 누르면 상태별 관리 메뉴를 노출한다.

상태별 메뉴 정책:

- 게시 완료: 다운로드, 삭제 등 완료 영상 관리
- 예약 게시: `예약 변경` 안에서 예약 일시 변경과 지금 게시를 함께 처리
- 게시 실패: `게시 설정 변경` 안에서 설정 수정과 다시 게시를 함께 처리
- 삭제와 같은 위험 동작은 위험 컨펌 팝업을 사용한다.

## 8. 상태 및 예외 정책

### 8.1 로그인·회원

- MVP 인증 수단은 Google 로그인 하나만 제공한다.
- 최초 로그인은 회원가입과 로그인을 별도 화면으로 나누지 않는다.
- Google 인증이 성공하면 사용자 계정 존재 여부에 따라 계정 생성 또는 로그인을 처리한다.
- 인증 처리 중에는 로그인 버튼을 다시 실행할 수 없게 한다.
- 인증 실패 또는 사용자가 인증을 취소하면 서비스 계정을 생성하지 않는다.
- 로그인하지 않은 사용자는 홈·만들기·라이브러리·마이페이지에 접근할 수 없다.
- 로그아웃하면 인증이 필요한 화면에 접근할 수 없으며 랜딩으로 이동한다.
- 가입 이메일과 로그인 방식은 마이페이지의 계정 정보에 표시한다.
- 이메일 회원가입, 비밀번호 로그인, 비밀번호 찾기, 카카오·네이버 로그인은 MVP에서 제공하지 않는다.
- Google 계정과 향후 추가될 이메일·카카오·네이버 계정의 연결·통합 정책은 추후 확정한다.

### 8.2 버튼

- 필수값이 충족되지 않으면 다음·생성·게시 버튼을 비활성화한다.
- 비활성 버튼은 클릭 이벤트를 실행하지 않는다.
- 처리 중에는 중복 실행을 막는다.

### 8.3 캐릭터

- 캐릭터는 한 명 이상 설정할 수 있다.
- 여러 캐릭터를 순차적으로 추가할 수 있다.
- 주인공과 보조 인물을 구분한다.
- 보조 인물도 필요한 시각 정보는 저장한다.

### 8.4 세계관과 스토리

| 세계관 상태 | 스토리 정책 |
|---|---|
| 기존 세계관 선택 | 기존 스토리 선택, 새 스토리, 이전 이야기 이어가기 가능 |
| 새 세계관 만들기 | 이전 이야기 이어가기 비활성 |

### 8.5 생성

- 생성 요청 후 진행 상태를 표시한다.
- 생성 완료와 생성 실패를 구분한다.
- 다시 생성 시 새 작업으로 처리한다.
- 실제 크레딧 차감 시점과 실패 시 복구 정책은 백엔드 설계 전에 확정한다.

### 8.6 게시

- 즉시 게시와 예약 게시 중 하나를 선택한다.
- 예약 게시에는 유효한 미래 일시가 필요하다.
- 게시 요청 중 중복 실행을 막는다.
- 게시 실패 상태를 저장하고 재시도할 수 있어야 한다.

### 8.7 라이브러리

- 초기 6개를 로드한다.
- 더보기마다 6개를 추가한다.
- 필터나 정렬을 변경하면 목록을 첫 페이지부터 다시 조회한다.
- 카드 보기와 목록 보기의 선택 상태를 동일 세션에서 유지하는 방식을 고려한다.

- 계정 탈퇴

## 12. 개발자 전달 주의사항

- 화면에 보인다는 이유만으로 실제 API 연동까지 완료된 기능으로 간주하지 않는다.
- MVP 구현, 목데이터 구현, 추후 기능을 구분한다.
- 피그마에 없는 화면이나 정책을 추측해 추가하지 않는다.
- 공통 컴포넌트를 우선 재사용한다.
- 사용자 입력과 생성 상태를 페이지별 임시 값으로 흩어놓지 말고 플로우 단위 데이터 구조를 먼저 정의한다.
- 캐릭터·세계관·스토리를 하나의 텍스트 필드로 합치지 않는다.
- 비밀키를 React 환경변수에 넣지 않는다.
- 각 단계 완료 후 `npm run lint`와 `npm run build`를 실행한다.
