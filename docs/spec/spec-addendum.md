# AAY Studio 변경 및 추가 개발 명세

## 1. 문서 목적

기존 개발 명세 작성 이후 확정된 정보 구조, 제작 플로우, 라이브러리 관리 기능, 크레딧 정책 및 신규 화면을 반영한다.

본 문서와 기존 명세가 충돌할 경우 본 문서의 내용을 우선한다.

---

# 2. 제작 방식 재정의

기존의 `템플릿 적용 / 직접 만들기` 구분은 실제 기능 차이를 정확히 표현하지 못하므로 다음과 같이 변경한다.

| 기존 명칭 | 변경 명칭 |
|---|---|
| 템플릿 적용 | 스토리 영상 |
| 직접 만들기 | 자유 영상 |

Figma 프레임명도 다음과 같이 변경되어 있다.

- `Create - 템플릿 적용 - stepN` → `Create - 스토리 영상 - stepN`
- `Create - 직접 만들기 - stepN` → `Create - 자유 영상 - stepN`

코드의 라우트명, 컴포넌트명, 타입명, 주석 및 화면 표시 문구도 가능한 범위에서 변경된 명칭을 기준으로 작성한다.

예시:

```ts
type CreationType = 'story' | 'free'
```

---

# 3. 제작 방식별 정의

## 3.1 스토리 영상

캐릭터가 등장하고 세계관과 스토리를 기반으로 제작되는 영상이다.

사용자는 다음 요소를 설정하거나 기존 데이터를 불러올 수 있다.

- 캐릭터
- 세계관
- 스토리
- 영상 제작 템플릿 또는 제작 설정

캐릭터, 세계관, 스토리는 각각 별도의 데이터로 저장되며 독립적으로 재사용할 수 있어야 한다.

템플릿은 제작 방식 자체가 아니라, 스토리 영상을 간편하게 만들기 위한 프리셋으로 취급한다.

## 3.2 자유 영상

사용자가 원하는 영상 내용을 자연어로 입력하면 AI가 다음 내용을 추천하고 영상을 구성하는 방식이다.

- 연출 방향
- 장면 구성
- 영상 스타일
- 필요한 이미지·음성·자막 구성

자유 영상은 MVP에서 캐릭터, 세계관, 스토리 데이터와 연결하지 않는다.

ASMR, 풍경, 제품 영상, 분위기 영상처럼 고정 캐릭터나 연속적인 스토리가 필요하지 않은 콘텐츠를 포함한다.

---

# 4. 스토리 영상 Step2 변경

스토리 영상 Step2에서는 캐릭터, 세계관, 스토리를 한 화면에서 설정한다.

우측 탭 또는 스테퍼를 선택하면 해당 설정 영역으로 자동 스크롤한다.

---

## 4.1 캐릭터 설정

### 주인공

다음 방식 중 하나를 선택한다.

- 기존 캐릭터 선택
- 새 캐릭터 만들기

`새 캐릭터 만들기`를 선택하면 캐릭터 생성 팝업을 노출한다.

### 주변 인물

- 필요한 경우 여러 명을 추가할 수 있다.
- 주인공보다 시각적 일관성 요구가 낮더라도 반복 등장하는 인물은 캐릭터 데이터로 관리한다.
- 등장 비중이 작거나 신체 일부만 등장하는 인물도 필요한 시각적 특징을 저장할 수 있다.

---

## 4.2 세계관 설정

다음 옵션을 제공한다.

- 기존 세계관 선택
- 새 세계관 만들기
- 사용하지 않기

### 새 세계관 만들기

`새 세계관 만들기`를 선택한 경우에만 다음 요소를 노출한다.

- 세계관 설명 입력 textarea
- `N크레딧으로 AI 추천` 버튼

### AI 추천 동작

1. 사용자가 입력한 내용과 선택한 캐릭터 정보를 수집한다.
2. AI가 세계관을 추천한다.
3. 추천 결과를 세계관 입력 영역에 채운다.
4. 사용자는 결과를 직접 수정할 수 있다.
5. 추천 결과는 자동 저장하지 않는다.
6. 사용자가 다음 단계로 이동하거나 저장 동작을 완료했을 때 확정한다.

AI 추천을 다시 실행하면 추가 크레딧이 차감될 수 있다.

---

## 4.3 스토리 설정

다음 옵션을 제공한다.

- 새 이야기 만들기
- 이전 이야기 이어가기

### 새 이야기 만들기

`새 이야기 만들기`를 선택한 경우 다음 요소를 노출한다.

- 새로운 이야기에 대한 아이디어 입력 textarea
- `N크레딧으로 AI 추천` 버튼

### AI 추천 동작

1. 선택된 캐릭터 정보를 수집한다.
2. 선택하거나 새로 입력한 세계관 정보를 수집한다.
3. 사용자가 입력한 이야기 아이디어를 수집한다.
4. AI가 캐릭터와 세계관에 맞는 스토리를 추천한다.
5. 추천 결과를 입력 영역에 채운다.
6. 사용자는 결과를 직접 수정할 수 있다.
7. 추천 결과는 자동 저장하지 않는다.

### 이전 이야기 이어가기

- 기존에 저장된 스토리 중 하나를 선택한다.
- 선택한 캐릭터 및 세계관과 연결된 스토리를 우선 노출한다.
- 기존 이야기의 설정과 진행 내용을 기반으로 후속 이야기를 생성한다.

### 예외 정책

`새 세계관 만들기`를 선택한 경우에는 기존 스토리와 연결할 수 없으므로 `이전 이야기 이어가기` 옵션을 비활성화한다.

비활성 상태에서는 사용자가 선택할 수 없어야 한다.

# 5. 캐릭터 생성 팝업

캐릭터 생성 팝업에서는 다음 두 가지 생성 방식을 제공한다.

- 설명으로 만들기
- 이미지로 만들기

---

## 5.1 설명으로 만들기

입력 항목:

- 이름
- 캐릭터 설명
- 특징 또는 소품
- 대표 이미지
- 참고 이미지 최대 3장

### 대표 이미지

사용자가 입력한 캐릭터 설명을 기반으로 이미지를 생성한다.

버튼 문구:

```text
N크레딧으로 이미지 생성
```

### 참고 이미지

사용자는 다음 방식 중 하나를 사용할 수 있다.

- 기존 이미지 업로드
- AI 이미지 생성

AI 이미지 생성 버튼 문구:

```text
N크레딧으로 이미지 생성
```

업로드 자체에는 크레딧을 사용하지 않는다.

### 이미지 생성 정책

- 이미지 생성 전 현재 보유 크레딧을 조회한다.
- 크레딧이 충분하면 이미지 생성을 실행한다.
- 생성에 성공하면 설정된 크레딧을 차감한다.
- 생성에 실패한 경우 크레딧을 차감하지 않거나 자동 복구해야 한다.
- 재생성할 때마다 크레딧이 추가로 사용될 수 있다.
- 필수 설명이 입력되지 않은 상태에서는 이미지 생성 버튼을 비활성화할 수 있다.

# 6. 라이브러리 정보 구조

라이브러리는 생성 영상뿐 아니라 제작에 재사용되는 요소를 통합 관리한다.

상단 탭:

- 영상
- 캐릭터
- 세계관
- 스토리

별도의 LNB 2Depth는 만들지 않고 라이브러리 콘텐츠 영역의 탭으로 구분한다.

# 7. 영상 라이브러리

## 7.1 보기 방식

다음 두 가지 보기 방식을 제공한다.

- 카드 보기
- 목록 보기

기본값은 카드 보기다.

사용자가 변경한 보기 방식은 재방문 시 유지할 수 있도록 로컬 스토리지 또는 사용자 설정값으로 저장한다.

## 7.2 목록 보기

노출 항목:

- 미리 보기
- 제목
- 제작 유형
- 게시 상태
- 게시 정보
- 생성일
- 더보기 메뉴

### 열 너비

- 제목 영역에 가장 넓은 비율을 배정한다.
- 게시 정보는 예약 게시 일시가 한 줄로 표시될 수 있는 너비를 기준으로 한다.
- 나머지 열은 실제 콘텐츠 길이에 맞게 최소 너비를 지정한다.
- 각 열의 데이터는 가운데 정렬한다.
- 제목은 필요하면 좌측 정렬을 사용할 수 있으나 전체 목록에서 일관되게 적용한다.

### 미리 보기

- 실제 영상 썸네일을 노출한다.
- 내용을 식별할 수 있을 정도의 크기를 확보한다.
- 단순 아이콘 수준으로 지나치게 작게 만들지 않는다.

### 게시 상태

MVP 상태값:

- 게시 완료
- 예약
- 실패

`게시 전` 상태는 사용하지 않는다.

게시 완료 상태에서는 게시 일시 뒤에 `게시`라는 문구를 중복해서 붙이지 않는다.

예시:

```text
게시 완료 | 2026.07.30 18:00
```

### 더보기 메뉴

텍스트로 작성한 기호를 사용하지 않고 Figma의 `more` 아이콘을 사용한다.

상태별 메뉴는 다음 정책을 따른다.

#### 게시 완료

- 영상 상세
- 게시 설정 변경
- 삭제

#### 예약

- 영상 상세
- 예약 변경
- 삭제

`지금 게시` 기능은 별도 메뉴로 제공하지 않고 예약 변경 기능에 포함한다.

#### 실패

- 영상 상세
- 게시 설정 변경
- 삭제

`다시 게시` 기능은 게시 설정 변경에 포함한다.

# 9. 세계관 라이브러리

세계관은 이미지가 필수 데이터가 아니므로 카드/목록 보기 전환 기능을 제공하지 않는다.

한 가지 목록 형태만 사용한다.

## 9.1 세계관 목록

노출 정보:

- 세계관 이름
- 세계관 요약
- 연결된 캐릭터 수
- 연결된 스토리 수
- 최근 수정일
- 더보기 메뉴

## 9.2 세계관 상세

정보 영역의 최대 너비는 `850px`로 설정한다.

별도의 `세계관 정보` 서브타이틀은 사용하지 않는다. 페이지 제목인 `세계관 상세`와 의미가 중복되기 때문이다.

노출 정보:

- 세계관 이름
- 세계관 설명
- 세계관 규칙
- 시간적 배경
- 공간적 배경
- 연결된 캐릭터
- 연결된 스토리
- 생성일
- 수정일

버튼:

- 수정
- 삭제
- 새 세계관 만들기

# 11. 생성 및 수정 화면

## 11.1 캐릭터

캐릭터 생성에는 캐릭터 생성 팝업을 사용한다.

캐릭터 수정은 캐릭터 상세 화면의 `수정` 버튼으로 진입한다.

수정 화면은 생성 화면과 동일한 정보 구조를 사용하되 기존 값이 입력된 상태로 노출한다.

## 11.2 세계관

세계관 생성과 수정은 동일한 폼 컴포넌트를 사용한다.

차이점:

- 생성: 초기값 없음
- 수정: 기존 저장값을 초기값으로 제공
- 생성 버튼 문구: `만들기`
- 수정 버튼 문구: `수정 완료`

세계관 생성 화면에도 `N크레딧으로 AI 추천` 기능을 제공할 수 있다.

AI 추천 결과는 입력값으로 반영하며 사용자가 수정할 수 있어야 한다.

## 11.3 스토리

스토리 생성과 수정은 동일한 폼 컴포넌트를 사용한다.

차이점:

- 생성: 초기값 없음
- 수정: 기존 저장값을 초기값으로 제공
- 생성 버튼 문구: `만들기`
- 수정 버튼 문구: `수정 완료`

스토리 생성 화면에도 `N크레딧으로 AI 추천` 기능을 제공할 수 있다.

스토리 AI 추천 시 선택된 캐릭터와 세계관 정보를 함께 사용한다.

- 캐릭터 수정
- 새 세계관 만들기
- 세계관 수정
- 새 스토리 만들기
- 스토리 수정

예시 문구:

```text
캐릭터를 만들었어요.
세계관 수정을 완료했어요.
스토리를 만들었어요.
```

버튼 텍스트는 개발 과정에서 상황에 맞게 변경할 수 있다.

Alert를 닫으면 해당 요소의 상세 화면으로 이동한다.

# 13. 삭제 정책

라이브러리의 영상, 캐릭터, 세계관, 스토리를 삭제할 때는 공통 `위험 실행 Confirm 팝업`을 노출한다.

바로 삭제하면 안 된다.

## 삭제 흐름

1. 사용자가 더보기 메뉴 또는 상세 화면에서 삭제를 선택한다.
2. 위험 실행 Confirm 팝업을 노출한다.
3. 삭제 대상 이름과 삭제 영향을 안내한다.
4. 사용자가 삭제를 최종 확인한다.
5. 삭제 API를 호출한다.
6. 성공 시 목록 화면으로 이동하고 완료 Alert 또는 Toast를 노출한다.

## 연결 데이터가 있는 경우

캐릭터, 세계관, 스토리가 다른 데이터와 연결되어 있어도 기존에 생성된 영상 자체는 삭제하지 않는다.

삭제 전 다음 내용을 안내한다.

- 이후 새 영상 제작에서 해당 요소를 다시 선택할 수 없음
- 기존 영상은 유지됨
- 연결 정보 일부가 해제될 수 있음

실제 영구 삭제 대신 `deletedAt`을 사용하는 소프트 삭제 구조를 우선 고려한다.

# 14. 크레딧 부족 예외 정책

이미지 생성, AI 추천, 영상 생성 등 크레딧을 사용하는 모든 기능은 실행 전에 보유 크레딧을 확인한다.

## 공통 처리 흐름

1. 사용자가 크레딧 사용 버튼을 선택한다.
2. 서버에서 최신 보유 크레딧을 조회한다.
3. 필요 크레딧과 보유 크레딧을 비교한다.
4. 충분하면 작업을 실행한다.
5. 부족하면 공통 Confirm 팝업을 노출한다.

## 크레딧 부족 팝업

공통 `컨펌 팝업(공통)`을 사용한다.

예시:

```text
크레딧이 부족해요

이 작업에는 N크레딧이 필요해요.
현재 보유 크레딧은 N크레딧입니다.
크레딧을 충전하고 계속할까요?
```

버튼:

- 취소
- 크레딧 충전

`크레딧 충전`을 선택하면 크레딧 충전 페이지로 이동한다.

결제 또는 충전 후 원래 작업 화면으로 돌아갈 수 있도록 복귀 경로를 유지한다.

크레딧이 부족한 상태에서는 생성 API를 호출하지 않는다.

---

# 15. 크레딧 표기 원칙

사용자가 버튼을 누르기 전에 비용이 발생한다는 사실을 알 수 있도록 AI 실행 버튼에 필요 크레딧을 표기한다.

예시:

```text
N크레딧으로 이미지 생성
N크레딧으로 AI 추천
N크레딧으로 영상 생성
```

현재 정확한 차감량이 확정되지 않았으므로 Figma에는 `N크레딧`으로 표시한다.

개발에서는 기능별 크레딧을 하드코딩하지 않고 서버 설정값 또는 크레딧 정책 테이블을 사용한다.

예시:

```ts
type CreditAction =
  | 'character_image_generate'
  | 'world_recommend'
  | 'story_recommend'
  | 'video_generate'
  | 'video_regenerate'
```

# 16. 공통 UI 구현 기준

Figma에 이미 정의된 컴포넌트와 컬러를 우선 사용한다.

임의의 컬러, 테두리, 아이콘, 폰트 크기를 추가하지 않는다.

## 버튼

- 높이: 44px
- 폰트 크기: 14px
- 상하 패딩: 10px
- 좌우 패딩: 20px
- 너비: Hug contents
- 기존 Active/Disabled 컴포넌트 사용

## 입력창 및 드롭다운

- 높이: 38px
- 기존 입력 컴포넌트 사용
- 드롭다운 아이콘은 텍스트 `v`를 사용하지 않는다.
- 기존 꺾쇠 아이콘을 사용한다.

## 아이콘

- 더보기: Figma의 `more` 아이콘 사용
- 이동 꺾쇠: 기존 드롭다운 꺾쇠 아이콘을 90도 회전하여 사용
- 텍스트 기호로 아이콘을 대체하지 않는다.

## 컬러

기존 페이지와 공통 컴포넌트에 사용된 컬러 스타일을 그대로 사용한다.

- 신규 임의 컬러 생성 금지
- 텍스트 컬러 임의 변경 금지
- 보더 컬러 임의 변경 금지
- 위험 실행 컬러는 기존 위험 버튼 컬러 사용
- 딤: `#000000`, opacity `50%`

## 상세 화면

라이브러리의 모든 상세 화면에서 정보 콘텐츠 영역의 최대 너비는 `850px`로 통일한다.

# 17. 구현 시 데이터 구조 고려사항

MVP에서 사용자 화면에는 프로젝트 메뉴를 노출하지 않는다.

다만 추후 하나의 콘텐츠 프로젝트를 여러 플랫폼에서 공통 사용할 수 있도록 데이터 구조는 프로젝트 단위를 고려한다.

```text
User
 └─ Project
     ├─ Characters
     ├─ Worlds
     ├─ Stories
     ├─ Contents
     └─ Platform Connections
         └─ YouTube Channel
```

여기서 `Project`는 YouTube 채널 자체가 아니라 다음 정보를 공유하는 콘텐츠 작업 단위다.

- 콘텐츠 콘셉트
- 캐릭터
- 세계관
- 스토리
- 영상 스타일
- 금지 표현

MVP에서는 YouTube만 연동하지만, 추후 같은 프로젝트의 영상을 TikTok과 Instagram에도 게시할 수 있어야 한다.

프로젝트 ID는 내부 데이터 구조에 포함하되 현재 사용자 화면에는 표시하지 않는다.

# 18. 구현 완료 조건

다음 조건을 모두 만족해야 한다.

- 제작 방식 명칭이 `스토리 영상 / 자유 영상`으로 변경되어 있다.
- 스토리 영상에서 캐릭터·세계관·스토리를 설정할 수 있다.
- 새 세계관과 새 이야기 입력 영역에 AI 추천 버튼이 있다.
- AI 추천 버튼에 크레딧이 표시된다.
- 캐릭터 이미지 생성 버튼에 크레딧이 표시된다.
- 크레딧 부족 시 공통 Confirm 팝업이 노출된다.
- 라이브러리에 영상·캐릭터·세계관·스토리 탭이 존재한다.
- 캐릭터와 영상은 카드/목록 보기를 지원한다.
- 세계관과 스토리는 단일 목록 형식을 사용한다.
- 각 요소의 상세·생성·수정 화면이 연결된다.
- 생성 및 수정 완료 시 공통 Alert가 노출된다.
- 삭제 시 위험 실행 Confirm 팝업이 노출된다.
- 상세 정보 영역의 최대 너비가 850px로 통일되어 있다.
- 기존 Figma 컴포넌트와 스타일을 재사용한다.
