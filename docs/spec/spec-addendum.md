# AAY Studio 개발 명세 추가·변경 사항

> 기준: 기존 개발 명세 작성 이후 확정된 내용
> 기존 명세와 충돌하는 경우 본 문서의 내용을 우선 적용한다.
> 화면 구현 기준은 최신 Figma 화면으로 한다.

---

## 1. 서비스 방향 변경

AAY Studio는 단순한 AI 영상 생성기가 아니라, 캐릭터·세계관·스토리의 일관성을 유지하며 콘텐츠 제작과 게시를 지원하는 AI Agent 기반 서비스로 확장한다.

핵심 가치는 다음 두 가지다.

1. 캐릭터의 시각적 정보를 저장하고 이후 영상에서도 동일한 외형을 유지한다.
2. 생성한 스토리를 저장하고 다음 콘텐츠에서 이어서 사용할 수 있다.

캐릭터, 세계관, 스토리는 각각 독립적으로 저장·선택·재사용할 수 있어야 한다.

---

## 2. 용어 변경: 채널 → 프로젝트

서비스 내부에서 콘텐츠 설정을 묶는 단위는 `채널`이 아니라 `프로젝트`로 정의한다.

### 프로젝트의 의미

프로젝트는 다음 정보를 묶는 콘텐츠 제작 단위다.

- 프로젝트 콘셉트
- 타깃
- 업로드 스타일
- 금지 표현
- 캐릭터
- 세계관
- 스토리
- 생성 영상
- 게시 이력

`채널`이라는 용어는 YouTube 채널, TikTok 계정 등 실제 외부 플랫폼 계정을 가리킬 때만 사용한다.

### MVP 노출 정책

- MVP에서는 프로젝트 선택·관리 화면을 사용자에게 노출하지 않는다.
- 현재 화면 흐름은 그대로 유지한다.
- 단, 백엔드 DB 구조에서는 주요 데이터가 프로젝트에 종속될 수 있도록 설계한다.
- MVP에서는 사용자가 하나의 기본 프로젝트를 사용하는 것처럼 처리할 수 있다.

예시 관계:

- Project 1:N Character
- Project 1:N World
- Project 1:N Story
- Project 1:N Video
- Project 1:N PlatformConnection

### 멀티 플랫폼 확장 고려

캐릭터·세계관·스토리·영상은 특정 플랫폼에 직접 종속시키지 않는다.

하나의 영상을 추후 YouTube, Instagram, TikTok에 각각 게시할 수 있어야 하므로 다음 개념을 분리한다.

- 콘텐츠 원본
- 플랫폼별 게시 정보
- 외부 채널 또는 계정 연결

MVP에서는 YouTube만 구현한다. Instagram·TikTok UI와 게시 기능은 이번 개발 범위에 포함하지 않는다.

## 3. 라이브러리 정보 구조 변경

라이브러리 상단 탭을 다음과 같이 구성한다.

2. 캐릭터
3. 세계관
4. 스토리

기존 예약 관리 기능은 별도 메뉴로 분리하지 않고 영상 라이브러리에 포함한다.

## 4. 템플릿 적용 Step 2 변경

템플릿 적용 Step 2에서 `새 캐릭터 만들기` 기능을 제공한다.

### 처리 흐름

1. 사용자가 `새 캐릭터 만들기` 선택
2. 캐릭터 생성 팝업 또는 화면 노출
3. 캐릭터 정보 입력 및 이미지 생성·선택
4. 캐릭터 저장
5. 라이브러리의 캐릭터 목록에 추가
6. 현재 Step 2의 선택값으로 새 캐릭터를 자동 적용

### 캐릭터 생성 정보

- 캐릭터 이름
- 캐릭터 설명
- 외형적 특징 또는 고정 소품
- 캐릭터 구분
  - 주인공
  - 주변 인물
- 대표 이미지
- 참고 이미지

### 이미지 정책

- 설명을 기반으로 대표 이미지를 생성할 수 있다.
- 사용자가 보유한 이미지를 선택하거나 업로드할 수 있다.
- 참고 이미지는 선택 사항이다.
- 참고 이미지 역시 사용자가 직접 선택하거나 AI로 생성할 수 있다.
- 캐릭터의 시각적 일관성은 AI 모델명이 아니라 저장된 대표·참고 이미지 정보를 기준으로 유지한다.

- 최근 수정일

- 수정

- 특징 또는 고정 소품
- 대표 이미지 수

- 이미지 등록 방식
- 이미지 생성 방식
- 사용 크레딧

## 8. 세계관과 스토리의 연결 정책

세계관과 스토리는 분리된 데이터로 저장한다.

- 하나의 세계관은 여러 스토리를 가질 수 있다.
- 하나의 스토리는 하나의 세계관에 연결되는 것을 MVP 기본 정책으로 한다.
- 스토리는 여러 캐릭터를 참조할 수 있다.
- 캐릭터는 여러 세계관과 스토리에서 재사용될 수 있다.
- 영상은 생성에 사용된 캐릭터·세계관·스토리의 ID를 저장한다.

### 새 세계관 선택 시 예외 정책

템플릿 적용 Step 2에서 사용자가 `새 세계관 만들기`를 선택한 경우:

- 스토리의 `이전 이야기 이어가기` 옵션을 비활성화한다.
- 새 세계관에는 이어갈 기존 스토리가 없기 때문이다.

### 옴니버스 정책

같은 캐릭터와 세계관을 유지하면서 매 영상마다 독립적인 이야기를 만들 수 있다.

따라서 다음 두 기능은 별도로 제공해야 한다.

- 캐릭터·세계관만 재사용하고 새 단편 만들기
- 기존 스토리의 다음 이야기 만들기

## 9. AI Agent 처리 방향

AI 추천은 단순 텍스트 자동완성이 아니다.

AI Agent는 다음 정보를 수집하고 검토한다.

1. 프로젝트 설정
2. 선택한 캐릭터
3. 선택한 세계관
4. 기존 스토리
5. 금지 표현
6. 이전 생성 결과

AI 추천 처리 흐름:

1. 관련 데이터 수집
2. 컨텍스트 분석
3. 추천 결과 생성
4. 캐릭터·세계관·스토리 간 정합성 검토
5. 부족한 설정 보완
6. 사용자에게 후보 제시
7. 사용자가 선택한 결과 저장

가능하면 AI 추천 결과는 3개의 후보로 제공할 수 있도록 데이터 구조를 고려한다.

이번 개발 단계에서는 실제 AI Agent 전체를 구현하지 않더라도, UI와 상태 구조가 향후 다음 상태를 처리할 수 있어야 한다.

- idle
- loading
- success
- error
- selected

## 10. 공통 상세 화면 규칙

라이브러리의 상세 화면은 동일한 레이아웃 규칙을 사용한다.

적용 대상:

- 영상 상세
- 캐릭터 상세
- 세계관 상세
- 스토리 상세

공통 규칙:

- 본문 정보 영역 최대 폭: 850px
- 페이지 상단 중앙: 상세 화면 제목
- 좌측: 목록으로 돌아가기
- 우측: 수정·삭제
- 중복 서브타이틀 사용 금지
- 삭제 시 공통 위험 컨펌 팝업 사용
- 디자인 토큰과 버튼 컴포넌트는 기존 Figma 컴포넌트를 재사용

## 11. 기존 공통 UI 규격 유지

- 버튼 높이: 44px
- 버튼 폰트: 14px
- 버튼 좌우 패딩: 20px
- 버튼 상하 패딩: 10px
- 입력창·드롭다운 높이: 38px
- 딤: `#000000`, opacity `50%`
- 기본 제목 텍스트: `#333333`
- 보조 텍스트: `#555555`
- 기본 카드·박스 보더: `#DDDDDD`
- 위험 버튼 및 위험 텍스트: 기존 디자인의 `#D00000`
- 임의의 신규 색상이나 버튼 스타일을 추가하지 않는다.

## 12. 현재 MVP 개발 범위

이번 MVP에서 구현:

- YouTube 연동
- 캐릭터 저장·선택·관리
- 세계관 저장·선택·관리
- 스토리 저장·선택·관리
- 영상 생성 흐름
- 검토
- 즉시 게시
- 예약 게시
- 라이브러리
- 크레딧 및 마이페이지
- Google 로그인

이번 MVP에서 구현하지 않음:

- 사용자에게 노출되는 프로젝트 관리 화면
- Instagram 게시
- TikTok 게시
- 멀티 플랫폼 Publish Manager
- 이메일 회원가입
- 카카오 로그인
- 네이버 로그인
- 채널 성과 분석
- AI 기반 성장 전략 추천

단, 위 기능을 추후 추가할 수 있도록 데이터 종속 관계를 강하게 결합하지 않는다.

## 13. 구현 시 주의사항

- 기존 개발 명세와 현재 Figma가 다르면 최신 Figma를 우선한다.
- 세계관과 스토리 목록은 같은 공통 리스트 컴포넌트를 사용한다.
- 세계관과 스토리 상세도 같은 공통 상세 레이아웃을 사용한다.
- 캐릭터 목록은 이미지가 중요하므로 카드형을 유지한다.
- 영상 목록은 카드·리스트 보기 전환 기능을 유지한다.
- UI에 아직 없는 프로젝트 선택 기능을 임의로 추가하지 않는다.
- 외부 플랫폼 계정과 내부 프로젝트를 같은 `channel` 데이터로 처리하지 않는다.
- 상세 페이지의 수정·삭제 버튼과 목록의 메뉴 기능이 중복되어도 정상 정책이다.
- 아직 화면이나 동작이 확정되지 않은 기능을 임의로 구현하지 말고 TODO로 분리한다.
