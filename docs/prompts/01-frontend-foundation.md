## 프롬프트

AAY Studio 개발 명세(`docs/spec/aay-studio-spec.md`)의 11장 "구현 우선순위" 중 **1단계: 프론트엔드 기반**만 진행해줘.
`CLAUDE.md`의 행동 지침을 반드시 따르고, 화면 수치는 Figma MCP(`figma-desktop`)로 실제 프레임을 조회해서 확인해줘.
Figma 파일: `https://www.figma.com/design/s1vcVinETNj4YPpZH4z35B/AAY`
공통 헤더, LNB, 버튼, 인풋/드롭다운, 팝업 3종에 해당하는 프레임을 각각 찾아서 조회하고, 특정 프레임을 못 찾겠으면 나에게 어떤 프레임(화면/컴포넌트명)을 열어서 링크를 줘야 하는지 알려줘.
MCP 조회가 실패하면 임의로 수치를 추측하지 말고 나에게 알려줘.

### 이번 단계 범위 (스펙 4장, 6장, 9장 참고)

1. **전역 스타일**
   - `docs/spec/aay-studio-spec.md` 9장 기준: 기본 폰트 `Noto Sans KR`, 데스크톱 기본 프레임 1280×832.
   - 색상·타이포·spacing 등 디자인 토큰을 SCSS 변수(또는 프로젝트에 맞는 방식)로 정리한다. 새 색상을 임의로 추가하지 말고 Figma에 있는 값만 사용한다.
   - 위험 컬러 `#D00000`, 팝업 딤 `#000000` 50%를 전역 토큰에 포함한다.

2. **라우팅**
   - 스펙 4.2 "권장 라우트" 표에 있는 경로로 라우터를 구성한다 (`/`, `/home`, `/create`, `/create/template`, `/create/template/setup`, `/create/manual`, `/create/manual/brief`, `/create/settings`, `/create/generating`, `/create/review`, `/create/publish`, `/library`, `/library/:videoId`, `/mypage`).
   - 이번 단계는 페이지 라우팅 뼈대만 구성한다. 각 페이지는 화면 이름만 표시하는 자리표시자(placeholder)로 두고, 실제 화면 구현은 2단계(정적 화면)에서 진행할 것이므로 지금은 만들지 않는다.
   - 라우터 등 새 패키지가 필요하면 어떤 패키지를 왜 쓰려는지 먼저 설명하고 내 승인을 받은 뒤 설치한다.

3. **공통 헤더 & LNB**
   - 스펙 4.1, 9장 기준: 헤더 높이 70px(로고/서비스명, 로그아웃), LNB 폭 180px(홈/만들기/라이브러리/마이페이지 메뉴 + 하단 보유 크레딧 표시).
   - 로그인 이후 화면에서만 노출되는 레이아웃 컴포넌트로 만든다 (실제 로그인 상태 판별 로직은 이후 단계에서 연결할 것이므로, 지금은 레이아웃 컴포넌트 구조만 잡는다).

4. **공통 컴포넌트**
   - 버튼: 높이 44px, 너비 hug, 글자 14px, 패딩 상하 10px·좌우 20px, radius 10px. variant는 주요 실행(검정 배경/흰 텍스트), 비활성(회색 배경/흰 텍스트), 보조 실행(흰 배경/`#555555` 테두리·텍스트), 위험 실행(`#D00000`)으로 구현한다.
   - 인풋/드롭다운: 기본 높이 38px, 라벨 분리 방식.
   - 공통 팝업 3종(일반 컨펌 / 위험 컨펌 / 얼럿): 폭 360px, 내부 좌우 여백 30px, 버튼 높이 44px, 딤 `#000000` 50%. 타이틀/버튼 문구는 호출 위치에서 바꿔 쓸 수 있는 props 구조로 만든다. 팝업 오픈 시 배경 스크롤을 막는다.
   - 이 컴포넌트들은 이후 모든 화면에서 재사용할 공통 UI이므로, 페이지 전용 컴포넌트와 분리된 위치(예: 공통 컴포넌트 디렉터리)에 만든다. 디렉터리 구조는 기존 프로젝트 관례를 우선 확인하고, 없다면 제안 후 진행한다.

### 하지 않을 것

- 실제 로그인/인증 연동, API 연동, 목데이터 기반 상태 분기는 이번 단계에서 하지 않는다 (3~4단계 범위).
- 각 페이지의 실제 화면 구성(2단계 범위)은 만들지 않는다.
- 스펙이나 Figma에 없는 화면·컴포넌트·색상을 추측해서 추가하지 않는다.
